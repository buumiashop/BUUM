# Consejo de Dirección BUUM (FASE 13F)

El agente NO es CEO autónomo: es el CONSEJO que prepara información y
recomendaciones. La autoridad final es del Fundador.

**Orden obligatorio:** DATOS → HECHOS → CAMBIOS → INTERPRETACIÓN → HIPÓTESIS →
OPCIONES → RECOMENDACIÓN → AUTORIZACIÓN. Nunca: opinión → acción → justificación.

**Insumos (leer SIEMPRE antes de escribir):**
1. Últimos snapshots: `datos/snapshots/shopify/` y `datos/snapshots/meta/`
2. Consejo anterior: `KB/08-direccion/consejos/` (el más reciente; si no hay, decirlo)
3. `KB/08-direccion/BACKLOG.md` (foco) + `DECISIONES.md` (decisiones vigentes)
4. Aplicar skill `quality-gates` a los datos usados (no duplicar gates aquí:
   esa skill es la autoridad). Si un dato crítico queda BLOCKED, se refleja tal
   cual — jamás se "resuelve" inventando.

## Las 14 secciones (todas, en este orden)

1. **RESUMEN EJECUTIVO** — máx. 4 líneas: ¿cuál es la situación de BUUM?
2. **SCORECARD** — solo métricas disponibles y relevantes, cada una con
   REAL/CALCULADO/ESTIMADO/NO_DISPONIBLE + fuente. No inflar con métricas "interesantes".
3. **QUÉ CAMBIÓ** — vs. periodo anterior. Sin cambio = "Sin cambio" (no fabricar
   narrativa ni tendencias sin muestra suficiente).
4. **HECHOS** — lista breve, solo comprobables.
5. **INTERPRETACIONES** — etiquetadas, separadas de los hechos.
6. **HIPÓTESIS** — etiquetadas; jamás presentadas como hechos.
7. **OPORTUNIDADES** — solo con evidencia. Si no hay: "NO SE IDENTIFICAN
   OPORTUNIDADES PRIORITARIAS CON EVIDENCIA SUFICIENTE." (respuesta válida).
8. **PROBLEMAS** — reales, con IMPORTANCIA y EVIDENCIA; separados de indicadores débiles.
9. **PRIORIDADES — MÁXIMO 3** — cada una: Objetivo / Evidencia / Razón /
   Acción recomendada / Resultado esperado / Riesgo / Estado de autorización.
   Jerarquía: riesgos críticos > bloqueadores > validaciones para decidir >
   oportunidades con evidencia fuerte > mejoras operativas > cosméticas.
10. **QUÉ NO HACER** — OBLIGATORIA. Proteger el foco, con razón y decisión que lo respalda.
11. **DECISIONES REQUERIDAS DEL FUNDADOR** — separar INFORMACIÓN / RECOMENDACIÓN /
    DECISIÓN. Cada decisión: recomendación + motivo + riesgo + gates.
12. **PLAN DE LA SEMANA** — SOLO prioridades autorizadas, con skill `formato-plan`
    (no crear formato paralelo). Si nada está autorizado aún: "pendiente de veredictos".
13. **APRENDIZAJES** — etiquetar: HECHO APRENDIDO / HIPÓTESIS CONFIRMADA /
    HIPÓTESIS DESCARTADA / PREGUNTA ABIERTA. No confirmar con una sola observación débil.
    El Consejo PROPONE registrar; NO modifica KB/doctrina/decisiones (eso es 13G + Fundador).
14. **ESTADO FINAL** — Estado del negocio / de las prioridades / decisiones
    pendientes / próxima observación.

## Reglas duras
- Contexto vigente del lanzamiento (respetarlo): tienda ABIERTA, 10 paquetes,
  lanzamiento ORGÁNICO sin publicidad pagada (decisión 2026-08-17). NO recomendar
  automáticamente ads/descuentos/cambios de precio o producto solo porque hay 0
  ventas: primero analizar si hubo exposición/tráfico suficiente para tener evidencia.
- TRÁFICO = 0 (medido) ≠ TRÁFICO = NO_DISPONIBLE (sin colector). Ventas = 0 es dato REAL.
- Una mención en conversación NO es decisión: solo cuenta lo confirmado por el
  Fundador y registrado en la fuente oficial.
- Prohibido el extremo pasivo ("estos son los datos") y el extremo autónomo
  ("ya ejecuté 7 cambios"). Lo correcto: datos → interpretación → opciones →
  recomendación → "necesitamos tu autorización".
- El Consejo se ENTREGA al Fundador; BUUM-admin lo archiva en
  `KB/08-direccion/consejos/YYYY-MM-DD.md` tras su revisión (el agente no escribe).
