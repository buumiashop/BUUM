# Formato de Plan — plantilla obligatoria de dirección

> Se usa para todo trabajo importante (clase Crítica u Operativa). Tareas menores
> no necesitan plan formal. Autoridad de "terminado": `KB/00-gobierno/MODELO-DE-MADUREZ.md`.

```markdown
# PLAN — [nombre corto]
- **Fecha / Autor:** [fecha] · BUUM Director (o quien proponga)

## Objetivo
[Qué se busca lograr, en 1-2 líneas.]

## Situación actual
[Solo hechos verificables, con fuente (ESTADO-ACTUAL, datos, KB). Sin suposiciones.]

## Qué cambia en la realidad
[Si este plan se completa: qué podrá hacer/vender/medir BUUM que hoy no puede.]

## Valor esperado y VALUE GATE
[Valor concreto. Value Gate = la pregunta filtro de PVOE: ¿esto acerca a BUUM a
operar/vender HOY? Si la respuesta honesta es no → el plan va a roadmap/Congelador.]

## Evidencia necesaria
[Qué datos o confirmaciones hacen falta ANTES de ejecutar. Si faltan, el primer
paso del plan es conseguirlas, no suponerlas.]

## Pasos
1. [paso verificable]
2. …

## Riesgos
[Qué puede salir mal + mitigación.]

## Dependencias
[Qué debe existir/estar aprobado antes (otras tareas, decisiones, dinero, stock).]

## Criterio de TERMINADO
[Verificable y de realidad. HECHO ≠ TERMINADO: "escribí el código" es HECHO;
"la tienda cobra un pedido real" es TERMINADO. Usar los niveles del
MODELO-DE-MADUREZ (Construcción < Operación < Validación).]

## Qué se medirá después
[Métrica + cuándo se revisa. El resultado se anota en DECISIONES.md → la
realidad valida la recomendación.]

## Veredicto del Fundador
[pendiente / aprobado / rechazado / aprobado con cambios — copiar a DECISIONES.md]
```

**Regla:** BUUM propone el plan y espera veredicto. Recomendación ≠ aprobación.
